# Translator 第二阶段需求规格说明书

文档版本：1.0  
文档状态：待评审

维护仓库：`Wq5881898/translator`

## 1. 文档目的

本文规范 Translator 第二阶段的产品范围、功能需求、非功能需求、数据规则、验收标准和阶段边界，作为开发、测试、验收和后续维护的共同依据。

## 2. 产品定位

第二阶段建设一个轻量的 Windows 桌面伴侣应用，用于从浏览器、PDF、PPT、Word 和其他桌面应用中截取英文区域，在本地完成 OCR，再调用可替换的翻译 Provider，并复用第一阶段的学习、发音和收藏体验。

第二阶段与第一阶段属于同一产品，但交付物保持独立：

- 第一阶段：Chrome 浏览器插件，负责普通网页划词翻译；
- 第二阶段：Windows 桌面应用，负责跨应用截图识别和翻译；
- 两者均可单独安装和运行；
- 两者使用兼容的收藏数据格式，并支持用户主动同步；
- 第二阶段不得破坏或强制迁移第一阶段稳定版本。

## 3. 建设目标

1. 在任意常见桌面应用中通过全局快捷键发起区域截图。
2. 截图只在本机内存中存在，并在 OCR 完成后立即释放。
3. 在本地识别英文，允许用户在翻译前检查和修改文字。
4. 通过统一 Provider 接口完成英译中，默认优先使用浏览器桥接方案。
5. 展示中文翻译、单词音标和英文发音能力。
6. 在桌面端本地收藏单词和句子。
7. 与第一阶段插件主动同步收藏，保留 CSV 导入导出兼容性。
8. 保持轻量、模块清晰、容易测试和替换。

## 4. 非目标

第二阶段首版不包含：

- 自动监视屏幕或后台持续 OCR；
- 上传原始截图或完整文档；
- Word、PPT、PDF 专用插件；
- 账户系统和云端收藏同步；
- 自动传播收藏删除操作；
- 翻译次数统计；
- GPT 默认调用或共享 API Key；
- 未经授权的牛津、朗文等商业词典内容；
- 手机端、macOS 和 Linux 客户端；
- 浏览器商店或 Microsoft Store 正式发布。

## 5. 用户与典型场景

### 5.1 目标用户

- 日常阅读英文网页、PDF、PPT、Word 的英语学习者；
- 希望以较低成本获得快速翻译、发音和收藏能力的个人用户；
- 重视截图隐私，不希望把文档画面上传到云端的用户。

### 5.2 核心场景

1. 用户在 PPT 中看到英文，按快捷键框选区域，校对 OCR 文字后翻译。
2. 用户在浏览器内置 PDF 查看器中无法自动划词，改用桌面截图翻译。
3. 用户将单词收藏到桌面端，稍后主动同步到浏览器插件。
4. 浏览器桥接不可用时，用户仍能截图、OCR、编辑和收藏；配置其他 Provider 后可继续翻译。

## 6. 运行假设与依赖

- 首要目标平台为 Windows 10/11；最低兼容版本在技术验证模块中最终确定。
- 浏览器桥接 Provider 需要 Chrome 及兼容版本的 Translator 插件处于可连接状态。
- Chrome 本地 Translator API 的模型由浏览器管理，不能随桌面安装包分发。
- OCR 采用本地引擎；具体引擎需通过准确率、体积和许可验证后确定。
- 可选云端 Provider 由用户自行配置凭据、地址或额度。

## 7. 功能需求

### 7.1 应用基础与入口

- **S2-FR-001**：应用应能作为独立 Windows 程序安装、启动和退出。
- **S2-FR-002**：应用应提供托盘入口，可打开主窗口、设置和退出应用。
- **S2-FR-003**：应用应提供可配置的全局截图快捷键。
- **S2-FR-004**：快捷键冲突或注册失败时，应明确提示原因和修改方式。
- **S2-FR-005**：默认不要求用户注册账户或登录云服务。

### 7.2 区域截图

- **S2-FR-010**：用户触发快捷键后，应进入区域选择模式。
- **S2-FR-011**：区域选择层应支持常见多显示器和不同缩放比例。
- **S2-FR-012**：用户应能通过鼠标框选区域，并能按 `Esc` 取消。
- **S2-FR-013**：无有效区域时不应进入 OCR 和翻译流程。
- **S2-FR-014**：截图不得自动保存到文件、剪贴板或云端。
- **S2-FR-015**：截图仅在本机内存中用于 OCR，识别完成、取消、失败或超时后均应释放。
- **S2-FR-016**：应用不得在后台持续截屏或监控屏幕。

### 7.3 本地 OCR

- **S2-FR-020**：应用应在本地识别框选区域内的英文文字。
- **S2-FR-021**：OCR 过程中应显示可理解的进行中状态。
- **S2-FR-022**：OCR 失败、无文字、超时或引擎不可用时，应提供可恢复的错误信息。
- **S2-FR-023**：OCR 结果应进行基础空白和换行规范化，但不得擅自改写原意。
- **S2-FR-024**：OCR 引擎应通过统一接口隔离，允许后续替换。
- **S2-FR-025**：首版主要识别英文；其他语言识别不作为验收要求。

### 7.4 文字校对与分类

- **S2-FR-030**：OCR 完成后，必须先展示可编辑的识别文字。
- **S2-FR-031**：用户应能修改、复制、清空或取消识别结果。
- **S2-FR-032**：只有用户确认后，文字才可发送给翻译 Provider。
- **S2-FR-033**：应用应区分单词、句子和短段落，用于决定结果展示和收藏类型。
- **S2-FR-034**：空文本、没有英文字母或超过 5000 字符的输入应被拒绝并说明原因。

### 7.5 翻译 Provider

- **S2-FR-040**：翻译功能必须通过统一 `TranslationProvider` 接口调用。
- **S2-FR-041**：首个可测试版本应提供 Mock Provider，便于在无网络和无浏览器桥接时验证流程。
- **S2-FR-042**：首版默认正式 Provider 为 Browser Bridge Provider。
- **S2-FR-043**：Browser Bridge Provider 应只把用户确认后的文字发送给浏览器插件。
- **S2-FR-044**：浏览器插件应使用 Chrome 本地 Translator API 翻译，并把结果返回桌面端。
- **S2-FR-045**：桥接不可用时，应显示 Chrome、插件和连接状态的诊断信息。
- **S2-FR-046**：应用应允许以后新增 Azure、Google、LibreTranslate 或本地模型 Provider，而不修改截图、OCR、收藏和界面核心逻辑。
- **S2-FR-047**：可选云端 Provider 必须由用户主动启用并自行配置。
- **S2-FR-048**：翻译请求应具有请求 ID、超时、取消和防止旧结果覆盖新结果的机制。
- **S2-FR-049**：结果中应明确显示实际使用的 Provider。

### 7.6 翻译结果与发音

- **S2-FR-050**：结果区应显示英文原文和中文翻译。
- **S2-FR-051**：单词结果应尽可能显示音标；词典失败不得覆盖已经成功的翻译。
- **S2-FR-052**：应用应支持英语发音，并允许选择美式或英式语音。
- **S2-FR-053**：发音不可用时应显示原因，不得申请麦克风权限。
- **S2-FR-054**：用户发起新截图或新翻译时，应清除过期结果和测试信息。
- **S2-FR-055**：错误应显示在用户当前操作的窗口，不得让用户到其他页面寻找。

### 7.7 桌面端收藏

- **S2-FR-060**：用户可通过空心/实心爱心切换当前结果的收藏状态。
- **S2-FR-061**：收藏列表默认隐藏，通过按钮打开独立列表窗口或面板。
- **S2-FR-062**：单词收藏应保存英文、可选音标、中文翻译和首次收藏时间。
- **S2-FR-063**：句子或短段落收藏应保存英文、中文翻译和首次收藏时间。
- **S2-FR-064**：同一项目重复收藏不得产生重复记录。
- **S2-FR-065**：收藏应保存在桌面应用本地，不依赖账户和云端。
- **S2-FR-066**：用户应能删除单条收藏，但首版同步时不自动把删除传播到另一端。
- **S2-FR-067**：首版不记录或展示翻译次数。

### 7.8 收藏导入、导出与同步

- **S2-FR-070**：桌面端应支持与第一阶段兼容的 UTF-8 CSV 导入导出。
- **S2-FR-071**：导入前应全量解析和校验；任一行无效时不得部分写入。
- **S2-FR-072**：导入进度、成功和错误应在收藏窗口就近显示，并在结束后退出忙碌状态。
- **S2-FR-073**：应用应提供用户主动触发的“同步收藏”操作。
- **S2-FR-074**：同步应合并桌面端与浏览器端收藏，而不是默认用一端覆盖另一端。
- **S2-FR-075**：单词按规范化后不区分大小写去重；句子按规范化后的完整文本去重。
- **S2-FR-076**：冲突记录应保留最早的 `firstFavoritedAt`。
- **S2-FR-077**：同步应提供新增、合并、跳过和失败数量摘要。
- **S2-FR-078**：桥接不可用时，收藏同步失败不得影响桌面本地收藏。

### 7.9 设置、隐私与数据管理

- **S2-FR-080**：设置应至少包含快捷键、语音、默认 Provider 和可选 Provider 配置。
- **S2-FR-081**：保存设置后应明确显示成功并关闭或返回原窗口。
- **S2-FR-082**：凭据不得写入源代码、日志、导出文件或收藏记录。
- **S2-FR-083**：应用应提供隐私说明，明确截图生命周期和每种 Provider 发送的数据。
- **S2-FR-084**：用户应能清除桌面收藏、设置和本地诊断信息。
- **S2-FR-085**：清除操作应要求确认并说明不可恢复范围。
- **S2-FR-086**：日志默认不得记录截图、完整 OCR 文本、翻译文本、收藏内容或密钥。

## 8. 非功能需求

### 8.1 轻量与可维护性

- **S2-NFR-001**：不建设后端、账户、遥测平台或非必要常驻服务。
- **S2-NFR-002**：截图、OCR、翻译、收藏、同步和界面之间必须通过接口解耦。
- **S2-NFR-003**：桌面端优先采用 Windows 原生友好的轻量技术栈，避免仅为界面引入完整浏览器运行时。
- **S2-NFR-004**：各 Provider 应可独立测试和替换。

### 8.2 性能目标

- **S2-NFR-010**：快捷键触发到选择层显示的目标时间不超过 300 毫秒。
- **S2-NFR-011**：常见小区域 OCR 的目标完成时间不超过 3 秒。
- **S2-NFR-012**：翻译默认超时目标为 20 秒，并允许用户取消。
- **S2-NFR-013**：应用空闲时不得持续占用明显 CPU。

上述为首版工程目标，最终阈值以基准测试和目标设备验证为准。

### 8.3 隐私与安全

- **S2-NFR-020**：原始截图不得通过任何 Provider、桥接、日志或分析通道离开本机。
- **S2-NFR-021**：只允许发送用户确认后的 OCR 文字。
- **S2-NFR-022**：本地桥接应限制为当前用户和本机进程，拒绝远程网络访问。
- **S2-NFR-023**：跨进程消息应有来源校验、长度限制、请求 ID 和超时。
- **S2-NFR-024**：云端 Provider 必须展示最小上传提示和实际来源。

### 8.4 稳定性与可恢复性

- **S2-NFR-030**：任何 OCR、翻译、同步或导入失败不得破坏既有收藏。
- **S2-NFR-031**：应用异常退出后应能再次正常启动。
- **S2-NFR-032**：本地数据写入应具备事务或原子更新能力。
- **S2-NFR-033**：异步操作成功、失败和取消后均应退出忙碌状态。

### 8.5 兼容性

- **S2-NFR-040**：应验证单屏、多屏、不同 DPI 和常见 Windows 缩放设置。
- **S2-NFR-041**：应验证 Chrome 浏览器桥接的安装、断开、重连和扩展升级。
- **S2-NFR-042**：CSV 应继续兼容 Excel 和第一阶段插件。

## 9. 核心数据模型

### 9.1 收藏记录

```text
FavoriteEntry
  id                  稳定标识
  kind                word | sentence
  originalText        英文
  translatedText      中文
  phonetic            可选音标
  firstFavoritedAt    ISO 8601 时间
  updatedAt           本地更新时间
  source              desktop | browser | import
```

首版不得新增翻译次数作为必填字段。

### 9.2 翻译请求

```text
TranslationRequest
  requestId
  text
  sourceLanguage = en
  targetLanguage = zh-CN
  contentKind
```

### 9.3 翻译结果

```text
TranslationResult
  requestId
  originalText
  translatedText
  contentKind
  provider
  phonetic?
  completedAt
```

## 10. 错误状态

至少应定义并测试：

- 快捷键冲突；
- 截图取消或无有效区域；
- OCR 无结果、超时、初始化失败；
- 输入为空、非英文或过长；
- 浏览器未安装、扩展未连接或本地翻译模型不可用；
- Provider 超时、拒绝、限额或配置错误；
- 音标和发音不可用；
- 收藏读取、写入、导入、导出和同步失败；
- 本地数据库损坏或无写入权限。

每条错误必须包含：发生了什么、用户能做什么、已有数据是否安全。

## 11. 验收场景

### AC-01 跨应用截图翻译

在 PPT、Word、浏览器 PDF 或普通桌面窗口中按快捷键，框选英文后显示可编辑 OCR 文本；确认后得到中文翻译，原始截图未写入磁盘且未上传。

### AC-02 取消与失败恢复

用户按 `Esc`、OCR 无文字或 Provider 超时时，界面退出忙碌状态，显示就近错误，并允许立即重新截图。

### AC-03 浏览器桥接

Chrome 和插件可用时，桌面端能通过桥接获得 Chrome 本地翻译；断开插件后能明确显示连接失败，重新连接后无需重装桌面应用即可恢复。

### AC-04 独立运行

未安装浏览器插件时，桌面应用仍可启动、截图、OCR、编辑、管理桌面收藏和导入导出。

### AC-05 收藏与同步

两端各有不同收藏时，用户主动同步后两端均包含合并结果；重复项目不重复，首次收藏时间取最早值，删除不自动传播。

### AC-06 隐私验证

网络抓包、日志和本地文件检查均未发现原始截图；云端 Provider 仅收到用户确认后的文字。

## 12. 发布门槛

第二阶段首个可交付版本必须满足：

1. 所有 P0 功能完成并通过自动化测试；
2. 截图不落盘和不上传经过专项验证；
3. 浏览器桥接断开、重连和超时经过验证；
4. 收藏同步和 CSV 往返不丢失中文、引号、逗号和换行；
5. Windows 安装、卸载和重新安装测试通过；
6. 隐私说明、安装说明和测试报告完整；
7. 第一阶段插件回归测试通过。

## 13. 待技术验证事项

- Windows UI 技术栈和最低系统版本；
- Windows OCR 与 Tesseract 的准确率、体积、语言包和许可对比；
- 多显示器不同 DPI 下的截图坐标换算；
- Native Messaging 与 Windows Named Pipe 的桥接可行性；
- Chrome Translator API 在扩展后台生命周期中的稳定性；
- 桌面收藏使用 SQLite 的发布体积与升级策略；
- 安装器对桥接清单、注册项和卸载清理的处理。

这些事项属于第一批技术验证，不改变本文确定的产品边界。
